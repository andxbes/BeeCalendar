# BeeCalendar — технічна документація

> **Важливо:** цей документ потрібно оновлювати при кожній суттєвій зміні в проєкті.
> Див. розділ [Правила ведення документації](#правила-ведення-документації).

## Призначення

**BeeCalendar** — мобільний застосунок (Android / iOS / Web) для календарів матковода.
Користувач створює окремий календар на кожну партію або вулик, вказує дату прищепки (день 0)
і отримує хронологію етапів розвитку матки з нагадуваннями про важливі події.

## Стек технологій

| Шар | Технологія |
|-----|------------|
| Фреймворк | Expo SDK 56, React Native 0.85 |
| Мова | TypeScript (strict) |
| Маршрутизація | Expo Router (file-based) |
| Зберігання | AsyncStorage |
| Сповіщення | expo-notifications (лише нативні збірки) |
| Збірка | EAS Build |

## Структура проєкту

```
app/                    # Екрани (Expo Router)
  _layout.tsx           # Кореневий layout, синхронізація сповіщень при запуску
  index.tsx             # Список календарів
  calendar/[id].tsx     # Деталі календаря та етапи

components/             # UI-компоненти
  new-calendar-modal.tsx
  start-date-picker.tsx
  themed-text.tsx, themed-view.tsx

constants/
  stages.ts             # Етапи розвитку матки (тексти UI + логіка сповіщень)
  theme.ts              # Кольори та шрифти

lib/
  calendar-storage.ts   # CRUD календарів у AsyncStorage
  dates.ts              # Робота з датами (uk-UA)
  notifications.ts      # Локальні сповіщення

types/
  calendar.ts           # Тип BeeCalendar

assets/images/          # Іконки, splash, favicon

docs/
  TECHNICAL.md          # Цей файл
```

## Архітектура даних

### Тип `BeeCalendar`

```typescript
{
  id: string;                    // унікальний ідентифікатор
  name: string;                  // назва партії / вулика
  startDate: string;             // YYYY-MM-DD, день прищепки
  notificationsEnabled: boolean;
  createdAt: string;             // ISO 8601
}
```

**Ключ AsyncStorage:** `@beecalendar/calendars`

### Етапи (`constants/stages.ts`)

| День | Подія | Важливий | Сповіщення |
|------|-------|----------|------------|
| 0 | День прищепки | так | так |
| 3 | Перевірка приймання | ні | ні |
| 5 | Закриття маточників | ні | ні |
| 10 | Ізоляція / перенесення | так | так |
| 12 | Вихід маток | так | так |
| 17 | Обліт | ні | ні |
| 25 | Перевірка засіву | так | так |

Дата кожного етапу = `startDate` + `day` днів.

## Потік даних

```
Запуск (_layout.tsx)
  → requestNotificationPermissions()
  → loadCalendars()
  → syncAllCalendarNotifications()

Список (index.tsx)
  → loadCalendars() при фокусі екрана
  → створення → upsertCalendar() → syncCalendarNotifications()

Деталі (calendar/[id].tsx)
  → зміна дати / перемикач сповіщень → upsertCalendar() → syncCalendarNotifications()
  → видалення → cancelCalendarNotifications() → deleteCalendar()
```

## Сповіщення

- Працюють **лише** на Android/iOS у власній збірці (не Expo Go, не веб).
- Час нагадування: **08:00** у день важливого етапу.
- Ідентифікатор: `calendar-{id}-day-{day}`.
- Android-канал: `calendar-events` («Події календаря»).
- При зміні дати або вимкненні сповіщень старі заплановані сповіщення скасовуються і створюються заново.

## Локалізація

- Мова інтерфейсу: **українська**.
- Формат дат: `uk-UA` (`lib/dates.ts` → `formatDateUk`).
- Усі нові рядки UI та коментарі в коді — українською.

## Збірка та розгортання

```bash
npm install
npx expo start          # розробка
npm run build:apk       # EAS preview (APK), потрібен EXPO_TOKEN у .env
npm run download:apk    # завантажити останній APK у builds/
```

Профілі EAS (`eas.json`):
- `preview` — APK для тестування
- `production` — AAB для Google Play

## Екрани

### `app/index.tsx` — головний
- Список календарів з найближчим важливим етапом.
- FAB «+ Новий календар» → модальне вікно → перехід на деталі.

### `app/calendar/[id].tsx` — деталі
- Вибір дати прищепки.
- Перемикач сповіщень.
- Список усіх етапів (поточний день підсвічується).
- Видалення з підтвердженням.

## Правила ведення документації

**Оновлюйте `docs/TECHNICAL.md` разом із кодом**, якщо змінюється будь-що з переліченого:

| Зміна в коді | Що оновити в документації |
|--------------|---------------------------|

| Нове поле в `BeeCalendar` | Розділ «Архітектура даних» |
| Новий/змінений етап у `stages.ts` | Таблиця етапів |

| Нові npm-скрипти або профілі EAS | Розділ «Збірка» |
| Зміна сховища або ключів | Розділ «Архітектура даних» |
| Нова залежність, що впливає на архітектуру | Розділ «Стек технологій» |
